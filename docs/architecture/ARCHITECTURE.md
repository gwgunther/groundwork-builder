## What this is

Groundwork Builder is an AI-powered dental website generator. It takes a URL (existing practice site) and/or an intake JSON, runs an 11-phase pipeline (scrape → process → assemble → build → iterate → audit → report), and produces a fully built Astro static site plus a set of client-facing and operator-facing reports.

## Tech stack

| Layer | Choice | Notes |
|-------|--------|-------|
| Frontend framework | Astro v6 (static) | File-based routing, Content Collections for blog |
| Styling | Tailwind CSS v4 | Brand tokens injected by pipeline into `tailwind.config.mjs` / CSS |
| Language | TypeScript (src/) + JavaScript (pipeline) | Node.js for pipeline scripts |
| AI | Anthropic Claude API | Sonnet 4.6 for main tasks, Haiku 4.5 for image classification + citability |
| Interactivity | Alpine.js (CDN deferred) | Mobile menu, dropdowns, FAQ accordions |
| Hosting | Cloudflare Pages | Wrangler deploy; `public/_redirects` for 301s |
| CI/CD | GitHub Actions | Auto-deploy on push to `main` |
| CRM / ops DB | Cloudflare D1 (`groundwork-ops`) | `scripts/pipeline/lib/d1.js` + ops-dashboard Worker |
| Pipeline runtime | Local / CI (Railway Studio retired) | `build-site.js` / `audit-site.js`; Studio UI removed 2026-06-04 |

## Key architecture decisions

### SEO-first generation
Every page gets JSON-LD injected automatically via `BaseLayout.astro`: `Dentist` (LocalBusiness subtype), `MedicalProcedure` per service page, `FAQPage`, `BlogPosting`, `BreadcrumbList`, `WebSite`. `AggregateRating` is injected when `googleRating` + `reviewCount` are present in merged data. `sameAs` is populated from all social links found in bronze (Google Maps, Yelp, Facebook).

### Centralized config as generated artifact
`src/config/site.ts` is the single source of truth for practice info at runtime. The pipeline completely rewrites it via `injectSiteConfig()` — don't hand-edit after a build. Same for `navigation.ts` and `tailwind.config.mjs`.

### Preset-based vertical specialization
`presets/dental/` holds taxonomy, hub definitions, article rules, and schema defaults. Fork to add verticals. The dental preset auto-includes/removes service hubs based on detected services; general-dentistry hub is always kept.

### Variant system
8 section dimensions × 5 variants = 40 distinct visual states. The director picks a variant per dimension based on archetype. `derive-design-tokens` then overrides certain variants deterministically (e.g. warm archetype always gets a specific footer variant) to guarantee visual divergence between archetypes regardless of what the AI chose.

### Managed files pattern
Pipeline-generated sections in `.astro` files are wrapped with `<!-- MANAGED: start -->` / `<!-- MANAGED: end -->` markers. Re-runs regenerate only those sections, leaving surrounding user edits intact.

### Agent observability
Every AI call is logged through `lib/ai-call.js` — model, phase, input/output tokens, cost. Aggregated into `_pipeline/99-cost.json` and surfaced in the internal report. Run ledger stored in `_memory/runs.jsonl`.

## Environment variables

| `GSC_SITE_URL` | No | Google Search Console |
| `GBP_CLIENT_ID` / `GBP_CLIENT_SECRET` | No | Google Business Profile OAuth |
| `OPENAI_API_KEY` | No | Optional: GPT-4o-mini in AI citability audit |
| `GOOGLE_GEMINI_API_KEY` | No | Optional: Gemini Flash in AI citability audit |
| `GROUNDWORK_AGENT` | No | Set to `1` to enable designer agent by default |
| `GROUNDWORK_NO_CACHE` | No | Set to `1` to bypass silver page extraction cache |
| `CLOUDFLARE_ACCOUNT_ID` | CRM / deploy | Cloudflare account for D1 + Pages |
| `CLOUDFLARE_D1_DATABASE_ID` | CRM | D1 `groundwork-ops` database id |

## Build & deploy

```bash
# Development
npm run dev           # Astro dev server on localhost:4321

# Pipeline (URL → built site)
node scripts/pipeline/build-site.js --url https://example.com

# Build only
npm run build         # Astro static build to dist/

# Deploy
npx wrangler pages deploy dist   # Manual deploy to Cloudflare Pages
```

Automatic deploy runs via GitHub Actions on push to `main`.
